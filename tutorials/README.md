## Conformance notes

- **Standalone carrier (ST1–ST8, SRC4):** the primary path performs no clone, repository install or repository import in the kernel. One Section 2 cell carries, as text, the package's four modules (`__init__.py`, `pipeline.py`, `samples.py`, `metrics.py`) byte for byte, the stage runner `tutorial_stages.py`, the hash lock, the three snapshot manifests and the licence, writes each into a fresh run directory and verifies it against `CARRIED_HASHES`, stopping on a mismatch.
- **Isolated environment (RUN1, RUN10, ENV1, ENV2, ENV6, §25.13):** nothing is pip-installed into the kernel, which imports only the standard library, `IPython.display` and (for the BYOD upload) `google.colab`. A pinned `uv` wheel (URL, size and SHA-256) builds a managed CPython 3.12.12 virtual environment and installs `requirements-colab.lock.txt` with `--require-hashes --only-binary :all:`; the lock is compiled from the `pyproject.toml` pins for manylinux x86_64. `run_stage` runs one stage per process (`weights` → `prepare` → `encode` → `frozen` → `adapt` → `evaluate` → `reload`, then the `activity`), streams its output to the cell and `logs/`, and re-raises a failed stage's own error type and message as a kernel `RuntimeError`. Stages communicate only through files in the run directory (the dataset record and digest, the caption-embedding cache, the adapter artifact, JSON records).
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when a carried file, its recorded SHA-256, the lock or the manifests differ from the repository, when the lock stops pinning a `pyproject.toml` pin, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** staging fetches only absent manifest entries, from the Hugging Face Hub at the immutable revisions; verification re-hashes every entry; every file is safetensors or JSON/text; nothing is unpickled and no remote code runs.
- **Stages (§4.1):** `fetch_sample_dataset` / `load_byod_dataset` → `validate_dataset` (masks attached, refusal probes) + `dataset_manifest` → seeded stratified split (36 / 12 / 12) → `encode_prompts` + `release_prior` → frozen `evaluate`, `generate`, `score_inpainting_preservation`, `score_generations` with the mean-fill floor and the original-photograph reference (baseline) → `adapt` with the in-memory reference values and `save_artifact` → the same measurements on the exported adapter, loaded in a fresh process (evaluation) → `from_artifact` in a second fresh process with the parity check against the in-memory values → a new caption inpainted into held-out photographs (inference).
- **Conditioning:** `evaluate` and `adapt` give the UNet the same nine-channel input as `diffusers` inference: noisy latents, masked latents and the keep-mask channel (`unet_keep_mask`, 1 = keep), while records keep the repository convention (255 = repaint).
- **Score semantics (UNC1–UNC4):** CLIP scores are scaled similarities, not probabilities; kept-region PSNR measures the MoVQ round trip, not edit quality; the denoising loss is the training objective. No threshold is set and no calibration is claimed.
- **Baselines and evidence (EVAL6/EVAL10):** the frozen model is measured before adaptation on the same seeded latents, noise, masks and generation seeds; a mean-colour fill is the no-model floor and the original photograph a reference line, not a ceiling (outputs can score above it; the report counts how many do per image). Every metric is labelled sample-sanity evidence from 12 held-out photographs with no dispersion estimate.
- **Split integrity (SPL1–SPL8):** seeded and stratified per species, no photograph in two splits (`check_split_disjoint`), validation selects the epoch, and the test photographs are used only for the final comparison. In BYOD mode the split is stratified within each caption (every caption with three or more photographs appears in every split), only pixel-identical copies are removed, and near-duplicates that cross splits are reported by `near_duplicate_pairs`; the random split assumes independent photographs. The smallest accepted BYOD set is 6 distinct photographs (for example six of one caption, or four of each of two captions).
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False`, so the default path never opens an upload dialog. When enabled, user records flow through the same validation, encoding, baseline, adaptation, evaluation, export, reload and inference stages after a re-run from Section 4; every stage is a fresh process, so the baseline is always measured on an unadapted pipeline. A row without a `mask` gets the centre mask, and the stage reports how many did. Refusals name the row, the id and the file, and an invalid zip stops Section 4 with a kernel `RuntimeError` that repeats the refusal.
- **Guided layer (GDL1–GDL15, §3.5):** the opening names the intended learner, the GPU requirement and **How to use this notebook** (Run all, form fields, Infrastructure cells, section tags, predictions and sample answers), a **Roadmap** and an **Input → Model/System → Output** contract, observable learning objectives and a collapsible **Glossary**. Sections 4, 6, 7, 8 and 10 ask the learner to **Predict before running**; Sections 6 and 8 state the **Question tested**; **Expected result** / **What to notice** notes follow each principal stage; five **Check your reasoning** boxes and the conclusion scaffold carry sample answers. Section 10 is the optional **Predict → Change one thing → Run → Observe → Explain** activity on the mask size, running after every required output is written (`RUN_ACTIVITY` turns it off). Sections 1–3 are **[Engineering]** infrastructure: their four cells (runtime check, carrier, isolated install, snapshot staging) are collapsed (`cellView: form`, `jupyter.source_hidden`) and titled `# @title Infrastructure: …`; the learner cells each call `run_stage`, and **Where the code runs** explains the stage processes. Every numbered section is tagged **[Concept]**, **[Evaluation practice]** or **[Engineering]**. A **Troubleshooting** table and a **Conclude with evidence** scaffold close the notebook, and the prose says "notebook" throughout.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
